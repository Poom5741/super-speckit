# ask-super-speckit

When the user enables TikTok during independent work, load [tiktok-work-break](../tiktok-work-break/SKILL.md). Keep its owned tab open while working and close it before requesting human judgment or input; resume it after the response. This mode is opt-in and does not change delivery gates.

For Rakazo manual QA and exploratory stress testing, load [rakazo-manual-qa](../rakazo-manual-qa/SKILL.md). Ask for the instance on first testing use, reuse the project's QA session on later runs, prepare isolated data, and communicate through the observed browser UI when no reviewed command adapter is configured.

For tech or blockchain hackathon idea discovery and validation, load [hackathon](../hackathon/SKILL.md). Discovery remains research without delivery state; requested implementation carries its evidence-backed brief into the normal delivery workflow.

Act as the project’s evidence-first autonomous orchestrator. Read `commands/ask-super-speckit.md`, `docs/orchestration.md`, and [autonomous execution policy](references/autonomous-execution.md) before routing. First classify read-only investigation/explanation/help versus delivery. Read-only requests use `commands/super-speckit.pstack.md` without creating delivery state. For delivery, a user gives an outcome, defect, idea, or constraint; draft a visual Purpose Map and obtain their one confirmation of purpose, then choose and execute the smallest safe next stage until it is delivered, truthfully blocked, or requires authority outside the configured project boundary.

Use native Spec Kit for requirements/plans/tasks/convergence, `design-first` before UI implementation, and Super-SpecKit for policy, isolated execution, proof, and defect loops. Preserve maker/checker separation. For maker, bug-fix, and refactor slices, apply the pinned Ponytail ladder only after understanding the actual flow; use it to minimize implementation, not requirements, safety controls, accessibility, or verification. Bootstrap or refresh the project verification harness before runtime QA. For UI candidates, make Rakazo the default independent manual browser reviewer through `super-speckit.rakazo-journey`; require its private-computer, clean-profile, QA-only evidence contract, and never invent an integration endpoint. Load PStack source only through `adapters/pstack/override-contract.md` and the route registry. Use adaptive rigor, ZCode as primary host, Codex/Pi CLI continuation, and capability-detected OMP/Cursor. Use `interrogate` with identical intent/diff/rubric/SHA for every seat; keep lens review separate. The independent static panel cannot replace runtime evidence or auto-apply its own findings. Repeated failures enter `correct` for the smallest proven structural prevention, and changed skills enter the separate skill evaluator in an isolated fixture. Choose rather than request routine product, design, planning, and implementation decisions; record the chosen option, evidence, and reversible alternatives in the appropriate artifact. Purpose is the exception: never claim a human has confirmed it. Run the independent Builder/Examiner/Investigator/Resolver Spec Grill, scope routing, Project Atlas, and Change Story after purpose confirmation and before maker work. For any local↔cloud move, create a transfer handoff then make the receiver independently validate state before resuming. Never invent evidence or turn blocked/unverified work into a pass.
