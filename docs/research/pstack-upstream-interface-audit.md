# PStack upstream interface audit

Date: 2026-10-06. Research only. Audited local source at `e5a8186d7b43be8d6ac4452440fbead5f1a51c70` in the `cursor/plugins` repository. Links below pin that exact revision. Statements about scripts describe source behavior; host portability conclusions are inferences from those interfaces.

## Executable capabilities and boundaries

PStack's executable tools are smaller than its workflow library. `orch` is plain-file bookkeeping, and `watch-pr` observes GitHub PRs. Neither executable launches agents, runs product verification, or merges PRs. Those actions remain instructions to the host agent. The scripts package declares only Commander 14.0.0 as a runtime dependency, with Bun types and TypeScript as development dependencies. The entry points use Bun, including `import.meta.dir`, `Bun.spawnSync`, and executable Bun shebangs. Bootstrap hashes `package.json` plus `bun.lock`, installs with `bun install --frozen-lockfile` when its cached install key is missing or stale, writes that key, then restarts the entry point. Importing the standalone tool therefore has a package-install side effect on first use. [Package](https://github.com/cursor/plugins/blob/e5a8186d7b43be8d6ac4452440fbead5f1a51c70/pstack/skills/poteto-mode/scripts/package.json), [bootstrap](https://github.com/cursor/plugins/blob/e5a8186d7b43be8d6ac4452440fbead5f1a51c70/pstack/skills/poteto-mode/scripts/bootstrap.ts).

`orch` accepts `--store` or `ORCH_STORE`, JSON output, and explicit lock stealing through `--force`. Its command groups cover units, verification ledger, inbox pointers, parked gates, frontier, standing orders, and rendered status. Initialization creates `units.tsv`, `ledger.tsv`, `inbox/`, `gates.md`, `preferences.md`, and `frontier.json`. Writes acquire a PID lock and atomically replace files using temporary files plus rename. A dead lock holder is reclaimed automatically. A living holder blocks writes unless forced. TSV cells remove tabs and newlines and quote leading spreadsheet formula characters. These mechanisms support cooperating local processes; they are not a distributed ownership service. [CLI](https://github.com/cursor/plugins/blob/e5a8186d7b43be8d6ac4452440fbead5f1a51c70/pstack/skills/poteto-mode/scripts/orch/orch.ts), [store](https://github.com/cursor/plugins/blob/e5a8186d7b43be8d6ac4452440fbead5f1a51c70/pstack/skills/poteto-mode/scripts/orch/store.ts).

The ledger keys entries by PR number and head SHA. Recording the same pair replaces its row. Its allowed verdicts are `live-ui-verified`, `unit-test-verified`, `type-check-only`, `verifier-blocked`, and `verifier-failed`. Crucially, `ledger check` retrieves any existing row, including blocked or failed verdicts. Exit zero means a row exists, not that verification passed. Missing rows produce `NOT-VERIFIED` and exit 2. Evidence is a required string; the implementation does not open or validate the evidence artifact. Unit states are strings rather than an enforced transition machine. Thus an adapter must interpret verdicts and enforce workflow transitions explicitly. [Store ledger and units](https://github.com/cursor/plugins/blob/e5a8186d7b43be8d6ac4452440fbead5f1a51c70/pstack/skills/poteto-mode/scripts/orch/store.ts#L1243), [CLI error mapping](https://github.com/cursor/plugins/blob/e5a8186d7b43be8d6ac4452440fbead5f1a51c70/pstack/skills/poteto-mode/scripts/orch/orch.ts#L540).

The frontier command requires Graphite. It calls `gt --no-interactive log short --stack --reverse`, resolves each branch's PR using Graphite, and gets the branch SHA through local `git rev-parse`. An optional PR pin verifies the actual ordered list, rather than supplying an independent list. This is consistent with the standing-program Orchestrate playbook, which assigns one stacker and calls Graphite authoritative. It differs from Babysit, Shipping, and multi-phase-plan instructions that choose Origin or `gh` and explicitly avoid requiring Graphite. Integration must preserve this distinction or replace the frontier resolver; a blanket claim that PStack has no Graphite dependency would be false. [Resolver](https://github.com/cursor/plugins/blob/e5a8186d7b43be8d6ac4452440fbead5f1a51c70/pstack/skills/poteto-mode/scripts/orch/store.ts#L1105), [Orchestrate](https://github.com/cursor/plugins/blob/e5a8186d7b43be8d6ac4452440fbead5f1a51c70/pstack/skills/poteto-mode/playbooks/orchestrate.md#L77), [Shipping](https://github.com/cursor/plugins/blob/e5a8186d7b43be8d6ac4452440fbead5f1a51c70/pstack/skills/poteto-mode/playbooks/shipping.md).

## GitHub watcher contract

`watch-pr` offers single PR, connected stack, and frozen queued stack modes. JSON is default, with NDJSON during polling and optional human text. Defaults are 60-second polls, 300-second full-stack sweeps, no deadline, and five consecutive query errors. `--status-only` returns an observed status with exit zero; it does not assert readiness. The reader invokes `gh` and GitHub GraphQL. Checks use a nonempty `gh pr checks` result first, then paginated GraphQL rollup; both empty paths fail closed. Unknown enum values become query errors. These are GitHub-specific interfaces, even when adjacent playbooks support Origin through different commands. [CLI](https://github.com/cursor/plugins/blob/e5a8186d7b43be8d6ac4452440fbead5f1a51c70/pstack/skills/poteto-mode/scripts/watch-pr/cli.ts), [reader](https://github.com/cursor/plugins/blob/e5a8186d7b43be8d6ac4452440fbead5f1a51c70/pstack/skills/poteto-mode/scripts/watch-pr/github.ts).

The watcher distinguishes conflicts, review threads, failing CI, merge gates, pending checks, query failures, and completion. Exit codes are 2 for conflicts, 3 for threads, 4 for CI, 5 for timeout, 6 for merge gates, 7 for status-query failure, and 64 for invalid CLI arguments. Stack decisions rank blocker types across the stack, so a higher PR's conflict can outrank bottom PR CI. Queued mode retains its captured ordering, polls the first unmerged PR between sweeps, retries the failed sweep item, and emits completion only when the captured PRs are merged. It does not arm auto-merge. A `READY` result in simple mode is not proof of a merge. Shipping deliberately re-reads merged state after event wakes. [Policy](https://github.com/cursor/plugins/blob/e5a8186d7b43be8d6ac4452440fbead5f1a51c70/pstack/skills/poteto-mode/scripts/watch-pr/policy.ts), [Shipping step 8](https://github.com/cursor/plugins/blob/e5a8186d7b43be8d6ac4452440fbead5f1a51c70/pstack/skills/poteto-mode/playbooks/shipping.md).

## Workflow interfaces requiring host adaptation

The workflow library provides mechanisms worth retaining: Arena runs competing whole solutions, cross-judges them, and synthesizes selected parts; Architect uses Arena for competing interface sketches; Swarm partitions or races workers and aggregates evidence; Interrogate uses independent model reviewers plus lead judgment. Their execution contracts assume Cursor's Task tool, background/cloud workers, model slugs configured in `~/.cursor/rules/pstack-models.mdc`, and worktree isolation. These are recipes rather than portable orchestration APIs. A Codex port must map agent creation, waiting, model availability, cancellation, and concurrency instead of preserving tool names literally. [Arena](https://github.com/cursor/plugins/blob/e5a8186d7b43be8d6ac4452440fbead5f1a51c70/pstack/skills/arena/SKILL.md), [Architect](https://github.com/cursor/plugins/blob/e5a8186d7b43be8d6ac4452440fbead5f1a51c70/pstack/skills/architect/SKILL.md), [Swarm](https://github.com/cursor/plugins/blob/e5a8186d7b43be8d6ac4452440fbead5f1a51c70/pstack/skills/swarm/SKILL.md), [Interrogate](https://github.com/cursor/plugins/blob/e5a8186d7b43be8d6ac4452440fbead5f1a51c70/pstack/skills/interrogate/SKILL.md).

How traces implementation, Why reconstructs rationale from available evidence categories, and Teach combines their findings while preserving Why's confidence language. Reflect and Automate-me mine explicitly scoped Cursor transcripts and route findings into skill changes. They depend on host transcript access, structured question tools, and Cursor's built-in `create-skill`. Create-verification-skill writes `.cursor/skills/verify-<app>/`, seeds a feature map, and requires executing the generated recipe end to end, including cleanup that preserves evidence. These mechanisms are transferable, but paths and host controls must change. [How](https://github.com/cursor/plugins/blob/e5a8186d7b43be8d6ac4452440fbead5f1a51c70/pstack/skills/how/SKILL.md), [Why](https://github.com/cursor/plugins/blob/e5a8186d7b43be8d6ac4452440fbead5f1a51c70/pstack/skills/why/SKILL.md), [Teach](https://github.com/cursor/plugins/blob/e5a8186d7b43be8d6ac4452440fbead5f1a51c70/pstack/skills/teach/SKILL.md), [Reflect](https://github.com/cursor/plugins/blob/e5a8186d7b43be8d6ac4452440fbead5f1a51c70/pstack/skills/reflect/SKILL.md), [Automate-me](https://github.com/cursor/plugins/blob/e5a8186d7b43be8d6ac4452440fbead5f1a51c70/pstack/skills/automate-me/SKILL.md), [verification generator](https://github.com/cursor/plugins/blob/e5a8186d7b43be8d6ac4452440fbead5f1a51c70/pstack/skills/create-verification-skill/SKILL.md).

Autonomous run relies on Cursor `/loop` event wakes and heartbeats. Multi-phase plans assume ten live lanes on cloud VMs, `cursor-team-kit` control skills, and operator screenshots/video review for interaction changes. `check-plan.mjs` enforces this specific prose and checklist schema, including exact section names, ten numbered live lanes, screenshot evidence, and unit/live/perf rule text. It is a plan-format validator, not a verifier that evidence exists or tests pass. Worktree cleanup's audit helper fetches `origin/main`, reads GitHub PR metadata, scans Cursor transcript paths, and uses macOS `stat -f` and `date -r`. Although it deletes no worktrees, its fetch changes local refs. Its `awk` path parsing also assumes worktree paths without spaces. These details rule out copying it as a host-neutral read-only inspector. [Autonomous run](https://github.com/cursor/plugins/blob/e5a8186d7b43be8d6ac4452440fbead5f1a51c70/pstack/skills/poteto-mode/playbooks/autonomous-run.md), [plan validator](https://github.com/cursor/plugins/blob/e5a8186d7b43be8d6ac4452440fbead5f1a51c70/pstack/skills/poteto-mode/scripts/check-plan.mjs), [worktree audit](https://github.com/cursor/plugins/blob/e5a8186d7b43be8d6ac4452440fbead5f1a51c70/pstack/skills/poteto-mode/scripts/worktree-audit.sh).

## Verification and licensing

Executed against the pinned temporary checkout on 2026-10-06 with Bun 1.4.0: `bun install --frozen-lockfile`, `bun test orch watch-pr`, and `bun run typecheck`. Installation resolved Commander 14.0.0, bun-types 1.3.14, and TypeScript 7.0.2. All 52 tests passed with 206 assertions, and strict typechecking passed. Tests cover file-store semantics and locks, Graphite parsing through fixtures, watcher readiness, fallback parsing, stack discovery, retry/sweep cadence, rendering, and CLI errors.
